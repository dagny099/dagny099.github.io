# Pilot plan: "My Podcast Loves, as a graph"

Status: planned 2026-10-03, build in the next session.
Lives in `_planning/` (underscore folder, not a collection, so Jekyll does not publish it).

## 1. What the pilot is

A page on barbhs.com that shows the podcast episodes I have listened to as an
interactive graph. Shows are colored, a slider filters by date (listen date by
default), and clicking an episode opens a side panel with its metadata and my
notes. New episodes get added conversationally in a Claude Code session through
a repo skill that drafts the entry, asks me to confirm, and opens a PR.

**Done means:**
- `/listening/` renders a graph of 5–10 seeded episodes across at least 3 shows.
- Every episode also has its own page at `/listening/<slug>/`.
- Saying "I just listened to X, add it" in a Claude Code session in this repo
  produces a PR with one new `_listens/` file (plus any new person/show/topic
  entries), and the graph updates when it merges.

## 2. Decisions from the interview

| Question | Decision |
|---|---|
| Source of truth | Jekyll collection `_listens/`, one markdown file per episode |
| Date axis | Store `listened_on` and `published_on`; slider defaults to `listened_on` |
| Notes privacy | Public. Notes render on episode pages and in the side panel |
| Seed | 5–10 episodes named in chat, resolved by Claude |
| Nav | Unlinked URL `/listening/` + a card on `/projects/`. Nav dropdowns are a separate decision later |
| Node types | Show, Episode, Person (guests and hosts), Topic |
| Topics | Small controlled list in `_data/podcast_topics.yml`; the skill proposes additions for approval |
| Enrichment | Session lookups only (feed, episode metadata, one-line guest bio). No Neo4j |
| Visualization | Fresh D3 page in the Meaning Layer style of `projects/graph.html` |
| Click | Side panel with notes, plus links to the episode page and the audio |
| Add flow | `.claude/skills/add-listen/` in this repo; writes on confirm, branch + PR |

Explicitly out of the pilot: Organization nodes, Spark/Idea nodes, Wikidata IDs,
nav dropdowns, Neo4j, transcripts.

## 3. Data model

### Files

```
_data/podcast_shows.yml     # one entry per show (including shows I only know via a guest)
_data/podcast_people.yml    # guests and hosts
_data/podcast_topics.yml    # controlled vocabulary, ~15–25 entries
_listens/<listened_on>-<show_id>-<short-slug>.md   # one per episode heard
assets/data/listens-graph.json                     # generated by Liquid, never hand-edited
```

### IDs

Borrowed from `podcast-ingest-agent/CONTRACTS.md` §1: lowercase snake-case slugs
of the normalized name (`katie_malone`, `superdatascience`). One function of the
name, so the same person added twice converges on the same id. The skill checks
for an existing id before creating one.

### `_data/podcast_shows.yml`

```yaml
- id: superdatascience
  name: SuperDataScience
  hosts: [jon_krohn]          # person ids; creates HOSTS edges
  feed_url: <from lookup>
  homepage: <url>
  itunes_id: <collectionId>   # lets the skill list episodes without the RSS host
- id: linear_digressions
  name: Linear Digressions
  hosts: [katie_malone, ben_jaffe]
  # No _listens entry needed. A show with zero listens renders as a hollow node,
  # reached through its host. This is how the Linear Digressions case shows up.
```

### `_data/podcast_people.yml`

```yaml
- id: katie_malone
  name: Katie Malone
  bio: "<one line, from lookup, confirmed by me>"
  links: { site: <url> }
```

### `_listens/2026-10-03-superdatascience-<slug>.md`

```yaml
---
title: "<episode title as published>"
show: superdatascience
episode_number: <int or omit>
published_on: <YYYY-MM-DD>
listened_on: 2026-10-03       # default today; approximate is fine (see listened_precision)
listened_precision: day       # day | month | year, for back-filled memories
guests: [katie_malone]
topics: [ml_education, careers_in_data]
episode_url: <url>
audio_url: <url, optional>
guid: "<rss guid or itunes trackId>"   # dedupe key
spark: "One sentence on what this made me think."
provenance:
  metadata: itunes | rss | websearch | manual
  guests: confirmed
---
Longer notes, optional. Rendered on the episode page and in the side panel.
```

### Graph JSON (`assets/data/listens-graph.json`)

Generated by a Liquid template (`layout: null`, `jsonify`). The shape matches
Graph Garnish (`nodes`, `links`, `type`, `provenance`) so tooling can move
between the two.

| Edge | From → To | Source |
|---|---|---|
| `HAS_EPISODE` | Show → Episode | `show` |
| `HOSTS` | Person → Show | `podcast_shows.yml hosts` |
| `GUEST_ON` | Person → Episode | `guests` |
| `COVERS` | Episode → Topic | `topics` |

People and topics are emitted from the data files. Ones that no episode or show
references get dropped client-side.

## 4. Pages

- `_config.yml`: add the `listens` collection (`output: true`,
  `permalink: /listening/:name/`) and a default `layout: listen`.
- `_layouts/listen.html`: an episode page with the metadata strip, spark, notes,
  "back to the graph", and other episodes with the same guest or topic.
- `listening/index.html`: a standalone full-page D3 graph, the same approach as
  `projects/graph.html` (EB Garamond / IBM Plex, paper/teal/coral tokens, dark mode).
  - Encoding: color is reserved for shows. Episodes take their show's color.
    People are ink, and topics are small sand-outlined nodes. Show hues come from
    a categorical palette checked for contrast in light and dark (load the
    `dataviz` skill when building). Past ~8 shows, the rest fold into a neutral
    "other" with a legend toggle.
  - Controls: a date range slider (with a toggle between listened and published),
    show toggles in the legend, and name search.
  - Click: the side panel shows show, guest(s), both dates, topics, spark, notes,
    and links to the episode page and the audio. Clicking a person or topic
    highlights its neighborhood.
  - Mobile: the graph stays above the panel, and the panel becomes a bottom sheet.
- `/projects/` card linking to `/listening/`, labelled as a pilot.

## 5. The add-listen skill

`.claude/skills/add-listen/SKILL.md`, plus stdlib-only helpers in
`scripts/listens/` (`scripts/` is already in Jekyll's `exclude`).

Flow:
1. Parse the utterance into a show, guest/topic hints, a recency hint ("recent-ish")
   and a listen date (default today).
2. Resolve the show: check `_data/podcast_shows.yml` first. If it isn't there,
   look it up (see §6) and draft a new show entry.
3. Find the episode: list recent episodes and rank them by guest or keyword match.
   Show me the top 3 candidates when it's ambiguous. Never guess silently.
4. Resolve people: match against existing ids. For a new guest, draft a one-line
   bio and check whether they host a show (that's the Linear Digressions pattern),
   and if so, offer to add that show with a `hosts` edge.
5. Pick topics from the vocabulary and propose any new topic separately.
6. Ask for the spark sentence and optional notes, in my words. Claude drafts
   nothing here unless I ask.
7. Show the full draft file, write it on confirm, then run `scripts/listens/validate.py`
   (ids resolve, dates parse, no duplicate `guid`) and `bundle exec jekyll build`.
8. Branch `listen/<slug>`, commit, push, open a PR.

`validate.py` also runs in a GitHub Action on PRs that touch `_listens/` or the
three data files.

## 6. Network constraint (found while planning)

From this cloud environment, the egress proxy blocks `itunes.apple.com` and
every podcast RSS host I tried (megaphone, omnycontent, anchor, art19,
simplecast, buzzsprout, podcastindex), through both curl and WebFetch.
WebSearch works.

Options, in order of preference:
1. **Allowlist `itunes.apple.com`** in the cloud environment's network settings
   (Custom, keep the package-manager defaults). The Search API returns `feedUrl`,
   and `lookup?id=<collectionId>&entity=podcastEpisode&limit=200` returns recent
   episodes with title, release date, URL and description. That would cover
   metadata for most "recent-ish" episodes with one domain and no RSS host.
   *Unverified: I could not call it from here. Test it first next session.*
2. Run the skill from a **local** Claude Code session (open network). The
   helper script reads RSS directly, reusing Graph Garnish's paginated feed
   parser idea (`graphgarnish/tools/build_network.py`).
3. **WebSearch-only fallback** in locked-down sessions: resolve from episode
   pages, set `provenance.metadata: websearch`, and leave `guid` and
   `episode_number` empty for a later fill.
